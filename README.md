# Used-Car Resale Price Predictor

End-to-end comparison of six regression models for a **synthetic Indian used-car dataset** (500,000 rows, 17 columns) and a Streamlit dashboard. The target is `Resale_Price_INR`; prices are modeled on `log1p` scale and reported back in INR with Indian digit grouping.

> **Synthetic-data notice:** the dataset is generated by a rule-based multiplicative price generator with roughly 4.5% log-normal noise. High scores validate the pipeline and the generator's rules, not the real Indian used-car market.

## Setup

Use Python 3.12 (the ML stack is pinned and tested there).

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The dataset is already in `data/indian_used_car_dataset.csv`.

## Run order

1. Build the dashboard catalog (also uses the canonical split for km-percentile warnings):

```bash
python -m src.build_catalog_options
```

2. Build/run the notebooks. The notebooks are already executed with saved outputs; to reproduce from scratch, run them top to bottom:

```bash
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/01_ridge.ipynb
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/02_random_forest.ipynb
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/03_xgboost.ipynb
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/04_lightgbm.ipynb
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/05_catboost.ipynb
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/06_mlp.ipynb
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/07_model_comparison.ipynb
```

You can also open each notebook and use **Restart & Run All**. Notebook 07 writes `artifacts/best_model.json`; the dashboard never hardcodes the winner.

3. Optionally inspect signed prediction bias and fit calibration factors:

```bash
python -m scripts.bias_report
python -m scripts.calibrate_models
```

`bias_report` writes `artifacts/bias_report.json` (global and segment-level signed bias for every model). `calibrate_models` writes `artifacts/calibration.json` with one multiplicative factor per model, learned on the validation split. Point either script at external labeled data with `--input path/to/labeled.csv`; use `--eval-input` to score calibration factors on a separate CSV.

4. Launch the dashboard:

```bash
streamlit run app/streamlit_app.py
```

## Pipeline summary

- Canonical 70/15/15 split stratified by price quantile bins, seed 42; indices saved in `artifacts/split_indices.npz`.
- Tuning on a 100k stratified subsample of **train only**, then refit on the full training split.
- Shared features: `Age`, `Ownership_Age`, `Km_Per_Year`, train-fitted `Km_Ratio`, `Delhi_Flag`, `Delhi_Restricted`, ordinal encodings, and `Model_Key`.
- `Delhi_Flag` covers Delhi, Gurugram, and Noida. `Delhi_Restricted` is true for diesel ≥10 years or petrol ≥15 years in those cities.
- `Original_Purchase_Price_INR` is excluded by default; notebook 07 contains a best-model-only ablation to quantify its leakage effect.
- Models: Ridge (RidgeCV + interactions), Random Forest, XGBoost, LightGBM, CatBoost, and an sklearn MLP with early stopping.
- Metrics: log R², log RMSE, log MAE, INR MAE, INR RMSE, MAPE, median APE. Test metrics are produced once from the untouched test set, then verified in notebook 07.
- Tree diagnostics use TreeSHAP for XGBoost/LightGBM/CatBoost. Random Forest uses permutation SHAP because exact TreeSHAP on the final 150-tree forest is prohibitively slow at this hardware budget.

## Dashboard

- Cascading Manufacturer → Model → body/fuel/transmission/displacement/year options from `artifacts/catalog_options.json`.

## Results

Notebook 07 recomputes every model on the untouched 75k-row test split and verifies the saved `metrics.json` values. The winner is **LightGBM** by test log-RMSE.

| Model | Test RMSE (log) | Test MAPE | Median APE | R² (log) |
|---|---:|---:|---:|---:|
| Ridge | 0.14479 | 11.33% | 9.31% | 0.98126 |
| Random Forest | 0.07785 | 6.02% | 4.77% | 0.99458 |
| XGBoost | 0.05328 | 4.22% | 3.52% | 0.99746 |
| **LightGBM** | **0.05021** | **3.99%** | **3.35%** | **0.99775** |
| CatBoost | 0.05577 | 4.29% | 3.48% | 0.99722 |
| MLP | 0.06746 | 5.19% | 4.09% | 0.99593 |
| Ensemble (top-3: LGBM/XGB/Cat) | 0.05013 | 3.99% | 3.36% | 0.99775 |
| Ensemble (all six) | 0.05817 | 4.62% | 3.83% | 0.99697 |
| LightGBM + original price (ablation only) | 0.04995 | 3.98% | 3.36% | 0.99777 |

**Selection notes**

- The top-3 ensemble is effectively tied with LightGBM (0.00009 lower log-RMSE); the individual model is simpler to explain and deploy, so it is the dashboard winner.
- A paired 2,000-resample bootstrap puts LightGBM's log-RMSE advantage over XGBoost at −0.00306 (95% CI −0.00327 to −0.00285), so LightGBM is reliably better than the runner-up.
- Adding `Original_Purchase_Price_INR` barely improves the generator's best model here (MAPE 3.99% → 3.98%), which is consistent with the synthetic generator making resale value mostly a function of the other listed attributes. It is still excluded from the default models as a leakage safeguard.
- Holding out 15 car models causes large degradation (LightGBM holdout MAPE 41.8%), because `Model_Key` target encoding cannot generalize to names never seen in training. CatBoost degrades least on that test (25.8%).
- Holding out manufacturing years 2024–2026 also degrades tree models (LightGBM 16.6% MAPE vs 3.8% baseline), because the model has no training examples at age 0–2. The MLP generalizes best there (8.5%).

See `artifacts/best_model.json`, `artifacts/metrics.json`, and `artifacts/generalization.json` for final numbers and diagnostics.

## Bias diagnostics and calibration

Metrics such as MAPE hide direction. `src/bias.py` adds signed diagnostics:

- `mean_signed_pct` / `median_signed_pct`: positive means over-prediction, negative means under-prediction.
- `mean_ratio`: predicted / actual (below 1.0 means under-prediction).
- `underprediction_rate`: share of rows where predicted < actual.
- `calibration_factor_log`: multiplicative correction from the mean log residual.
- `calibration_factor_inr`: total actual / total predicted.

On the canonical test split the models are not materially biased: LightGBM has `mean_signed_pct = +0.13%`, `mean_ratio = 1.0013`, and `underprediction_rate = 50.2%`. Large under-prediction therefore points to a different reference distribution (for example real listings versus this synthetic generator), app inputs that differ from the training row, or unseen models/years rather than a bug in the `log1p` conversion.

Calibration is opt-in. After `scripts/calibrate_models` writes factors, the dashboard exposes an **Apply saved bias calibration** checkbox and `predict_inr(..., calibrated=True)` applies them. Re-run calibration on the distribution you care about; factors fitted on the synthetic validation split are close to 1.0 and will not fix synthetic-to-real domain shift.

## Known limitations

- Synthetic data: the models learn the generator's rules, not real market behavior.
- The generator's ~4.5% log-normal noise sets a practical MAPE floor of roughly 4–6%.
- Rare car models, very old restricted diesels, and extreme kilometre values have less training support.
- The Streamlit app is a demonstration, not a valuation or lending tool.
